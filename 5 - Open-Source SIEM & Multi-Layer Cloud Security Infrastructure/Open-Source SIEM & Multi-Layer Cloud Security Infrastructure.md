# MSF,Splunk and Reverse Shell Attack Demonstration

## Overview
This project involved designing and implementing an open-source Security Information and Event Management (SIEM) system to secure a complex Infrastructure as a Service (IaaS) lab environment. The core objective was to bridge the semantic gap between raw hypervisor data and virtual machines by establishing real-time visibility across physical, orchestration, and cloud layers. By centralizing telemetry, the solution provides system administrators with a unified dashboard to rapidly identify and mitigate threats.

## Technical Stack
* SIEM: Wazuh (Manager, Indexer, and Dashboard)
* Infrastructure & Orchestration: MAAS (Metal as a Service), Juju, and OpenStack
* Environment: Ubuntu 22.04 LTS utilizing LXD containers  
* Data Processing: Custom Regex for log normalization and decoding  


## Infrastructure Architecture & Telemetry Pipeline

To bridge the semantic gap between physical hypervisors, orchestration agents, and tenant workloads, the SIEM architecture relies on a multi-tiered log ingestion pipeline. Telemetry flows from bare-metal nodes up to the OpenStack cloud control plane into a centralized Wazuh cluster deployed on Ubuntu 22.04 LTS within LXD containers.  
* Physical Layer (MAAS): Ingests rack controller events, machine provisioning logs, and PXE booting telemetry
* Orchestration Layer (Juju & LXD): Captures application charm deployment states, model hooks, and container lifecycle events across LXD hosts
* Control Plane Layer (OpenStack): Ingests API traffic and authentication logs from Keystone (Identity), Nova (Compute), and Neutron (Networking)
* Centralized SIEM (Wazuh): Wazuh Agents and local rsyslog endpoints ship raw events to the Wazuh Manager, which decodes, correlates, and indexes them into the Wazuh Indexer for visualization on the Dashboard.


## Custom Decoders & Rule Engineering
Standard SIEM rules fail to parse non-standard logs generated by MAAS and Juju out of the box. In order to achieve deep operational visibility, custom XML/Regex decoders parse unstructured text fields into standardized, queryable key-value pairs (e.g., maas.user, juju.charm, juju.action).  
* Log Normalization: Custom regex extractors parse raw MAAS API requests and Juju hook executions, mapping source IP addresses, system user accounts, and action types into structured telemetry.
* MITRE ATT&CK Mapping: Security rules correlate parsed log fields against specific attack techniques to contextualize security events:
** T1110 (Brute Force): Triggered when repeated Keystone or SSH authentication failures occur within a short time window.
 > * T1078 (Valid Accounts): Alerts on anomalous API access, privilege escalation, or unapproved charm deployments executed via Juju controllers.
  T1070 (Indicator Removal): Generates high-severity alerts if system journals or control plane audit logs are tampered with or cleared.
